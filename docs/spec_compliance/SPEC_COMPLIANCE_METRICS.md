# Metrics Spec Compliance

This document tracks how the Ruby `metrics_api`, `metrics_sdk`, and `exporter/otlp-metrics` gems
align with the [OpenTelemetry Metrics specification](https://github.com/open-telemetry/opentelemetry-specification/tree/main/specification/metrics)
as of 2026-10-12 (`main` at `b39632863`).

Progress against the [Metrics: Stability Prep milestone](https://github.com/open-telemetry/opentelemetry-ruby/milestone/11)
is called out inline: **Fixed** means merged to `main`; **Tracking** names the open issue and/or PR.

### Changes since the 2026-08-19 review

- **Merged and verified in code:** #2302 (data point `flags`), #2309 (API: `advisory:`, optional
  `callback:`, `enabled?`, `bind`, `register_callback`/`unregister`), #2377, #2392 (exponential
  exemplar sizing), #2393 (one reader per provider), #2395 (no unit/description validation),
  #2416 (global provider opt-in), #2417 (duplicate/case-insensitive instrument registration),
  plus the 10s console interval (#2373) and the OTLP exporter's post-shutdown guard.
- **Newly recorded gaps:** SDK instruments lack `enabled?`/`bind` (API-24, SDK-44/45); OTLP
  temporality-preference handling deviates from the spec in four ways (OTLP-2).
- **Row line numbers:** rows marked **Fixed**/**Changed**/**Tracking** were re-checked against
  `main` on 2026-10-12. Line references in rows that carry no such marker were not re-verified
  and may have drifted after #2301/#2309/#2435.

## Methodology

- **Scope**: `specification/metrics/api.md`, `noop.md`, `sdk.md`, `data-model.md`,
  `sdk_exporters/otlp.md`, `sdk_exporters/in-memory.md`, `sdk_exporters/stdout.md`.
  `supplementary-guidelines.md` was reviewed and contains no MUST/SHOULD statements (purely
  informative), so it contributes no rows.
- **Requirement level**: only MUST and SHOULD statements are tracked. MAY/optional-feature
  statements are out of scope unless they're explicitly tracked in the org-wide
  `spec-compliance-matrix.md`.
- **§ numbering**: self-assigned per document (`API-N`, `NOOP-N`, `SDK-N`, `DM-N`, `OTLP-N`,
  `INMEM-N`, `STDOUT-N`), grouped in the order the requirement appears in the spec doc. These are
  not spec line/section numbers — the spec docs use plain markdown headers, not numbered clauses.
- **Stability**: taken from each section's own `**Status**: [Stable]` / `[Development]` /
  `[Mixed]` marker in the spec doc. `api.md` and `noop.md` are `Stable` at the document level
  ("except where otherwise specified"); `sdk.md`'s document-level status is `[Mixed]`, meaning
  stability varies by section — most sections carry their own explicit marker, and any that don't
  are treated as `Stable (unmarked)` per the spec's general convention that Stable is the default
  and Development/Experimental status is called out explicitly. `data-model.md` and the
  `sdk_exporters/*.md` docs don't use per-section markers at all and are treated as
  `Stable (unmarked)` throughout. This lets the gap summary separate "missing Stable MUST"
  (spec-alignment risk now) from "missing Development feature" (still in flux upstream, lower
  urgency).
- **Status legend**: ✅ Full · ⚠️ Partial · ❌ Missing · N/A Not applicable to this implementation.
- Every citation below was read directly from the referenced file/line at the time this document
  was written; none are taken on faith from a summary.

## Summary of gaps

Every remaining ❌/⚠️ row above, grouped by stability (Stable gaps first — these represent
spec-alignment risk *now*; Development gaps second — the upstream spec is still moving on these) and
then roughly by blast radius. Each item names its tracking issue/PR, or "untracked".

### Resolved since the last review

`schema_url` aside, the API surface is now complete: advisory parameters, optional callbacks,
post-creation callback registration (including on proxies), and `enabled?`/`bind` (API/proxy only).
SDK fixes: duplicate-registration warning (SDK-36), case-insensitive name conflicts (SDK-37),
no unit/description validation (SDK-39/40), exponential exemplar sizing (SDK-50), single-provider
readers (SDK-54), data point `flags` (DM-2/3/4), the 10s console interval (STDOUT-3) and the OTLP
exporter's post-shutdown guard (OTLP-11).

- **`MetricProducer`** (SDK-60): #2356, PR #2418 (open).
- **`Enabled`/`enabled?` on SDK instruments** (API-24, SDK-44): API/proxy have it, SDK instruments raise `NoMethodError`; untracked.
- **`schema_url`** on `MeterProvider#meter` (API-5, NOOP-2): #2380, #2381, #1708, PR #1719 (stale).
