# Metrics Spec Compliance

This document tracks how the Ruby `metrics_api`, `metrics_sdk`, and `exporter/otlp-metrics` gems
align with the [OpenTelemetry Metrics specification](https://github.com/open-telemetry/opentelemetry-specification/tree/main/specification/metrics)
as of 2026-10-06 (last full review: 2026-08-19).

**2026-10-06 update**: re-reviewed every row against `main` as of commit `88a7da9e9` and against the
open PRs on `open-telemetry/opentelemetry-ruby`. Merged since the 2026-08-19 review: #2302 (data
point `flags` field), #2301 (OTLP exporter post-shutdown export guard, stdout exporter's 10s default
interval), #2309 (advisory parameters, `Enabled`/`Bind` surfaced on the API, zero-callback async
creation, proxy callback registration/queueing), #2377 (proxy callback passthrough on upgrade),
#2392 (exponential-histogram exemplar reservoir sizing), #2393 (one `MetricReader` per
`MeterProvider`), #2395 (SDK no longer validates `unit`/`description`), #2416 (global `MeterProvider`
accessor moved behind an opt-in require, mirroring the same change already made to
`opentelemetry-logs-api`). Each is reflected in the rows below with updated citations. Open PRs that
would close a remaining gap are noted inline in the relevant row and are not treated as "done" until
merged.

## Methodology

- **Scope**: `specification/metrics/api.md`, `noop.md`, `sdk.md`, `data-model.md`,
  `sdk_exporters/otlp.md`, `sdk_exporters/in-memory.md`, `sdk_exporters/stdout.md`.
  `supplementary-guidelines.md` was reviewed and contains no MUST/SHOULD statements (purely
  informative), so it contributes no rows.
- **Requirement level**: only MUST and SHOULD statements are tracked. MAY/optional-feature
  statements are out of scope unless they're explicitly tracked in the org-wide
  `spec-compliance-matrix.md`.
- **§ numbering**: self-assigned per document (`API-N`, `NOOP-N`, `SDK-N`, `DM-N`, `OTLP-N`,
  `INMEM-N`, `STDOUT-N`), grouped in the order the requirement appears in the spec doc. These are
  not spec line/section numbers — the spec docs use plain markdown headers, not numbered clauses.
- **Stability**: taken from each section's own `**Status**: [Stable]` / `[Development]` /
  `[Mixed]` marker in the spec doc. `api.md` and `noop.md` are `Stable` at the document level
  ("except where otherwise specified"); `sdk.md`'s document-level status is `[Mixed]`, meaning
  stability varies by section — most sections carry their own explicit marker, and any that don't
  are treated as `Stable (unmarked)` per the spec's general convention that Stable is the default
  and Development/Experimental status is called out explicitly. `data-model.md` and the
  `sdk_exporters/*.md` docs don't use per-section markers at all and are treated as
  `Stable (unmarked)` throughout. This lets the gap summary separate "missing Stable MUST"
  (spec-alignment risk now) from "missing Development feature" (still in flux upstream, lower
  urgency).
- **Status legend**: ✅ Full · ⚠️ Partial · ❌ Missing · N/A Not applicable to this implementation.
- Every citation below was read directly from the referenced file/line at the time this document
  was written; none are taken on faith from a summary.

## Summary of gaps

Every ❌/⚠️ row above, grouped by stability (Stable gaps first — these represent spec-alignment risk
*now*; Development gaps second — the upstream spec itself is still moving on these, so they're
lower urgency) and then roughly by blast radius (an entirely-missing interface vs. a narrower
behavioral deviation). Each item notes an **Open PR** where one exists on
`open-telemetry/opentelemetry-ruby` that would close it; absence of a note means no open PR was
found addressing that row as of 2026-10-06.

### Fixed since the 2026-08-19 review

For reference — these no longer appear below: global `MeterProvider` accessor relocation (API-1,
#2416), advisory parameters accepted by the API (API-12/13/14/15, #2309), zero-callback async
creation (API-16, #2309), proxy/base-API callback registration (API-17/18, #2309, #2377),
unit/description validation removed from the SDK (SDK-39/40, #2395), exponential-histogram exemplar
reservoir sizing (SDK-50, #2392), one `MetricReader` per `MeterProvider` (SDK-54, #2393), OTLP
exporter post-shutdown export guard (OTLP-11, #2301), stdout exporter's 10000ms default interval
(STDOUT-3, #2301), and the data-point `flags` field existing on `NumberDataPoint`/`HistogramDataPoint`
(DM-9 downgraded from ❌ to ⚠️, #2302).

### Stable — missing entirely

- **`MetricProducer`/`MetricFilter`** (SDK-60/61): no way to plug a third-party metric source, or filter one, into a `MetricReader` alongside SDK-collected data. **Open PR**: [#2418](https://github.com/open-telemetry/opentelemetry-ruby/pull/2418) (currently has merge conflicts).
- **`Enabled()`/`Bind()` on real SDK instruments** (API-24/25 reclassified, SDK-44/45): #2309 added `enabled?`/`bind` to the API no-op classes and `ProxyInstrument`, but no SDK instrument class implements either — calling them on a real, SDK-backed (or upgraded-proxy) instrument now raises `NoMethodError` rather than behaving as documented. No open PR found addressing the SDK side specifically.
- **`schema_url`** on `MeterProvider#meter` / View selection (API-5, NOOP-2, SDK-12): silently dropped if passed; a `since 1.4.0` MUST. **Open PR**: [#1719](https://github.com/open-telemetry/opentelemetry-ruby/pull/1719) (stale — opened 2026-08-20 with no recent activity).
- **Case-insensitive instrument name-conflict detection** (SDK-37). **Open PRs**: [#2398](https://github.com/open-telemetry/opentelemetry-ruby/pull/2398) and [#2417](https://github.com/open-telemetry/opentelemetry-ruby/pull/2417) (overlapping — see SDK-36/37 rows).
- **Redirect following** (OTLP-10): `handle_redirect` is still a literal no-op. **Open PR**: [#2411](https://github.com/open-telemetry/opentelemetry-ruby/pull/2411).
- **Post-shutdown blocking on the base `MetricReader`** (SDK-56): `MetricReader#shutdown` still sets no effective guard, so `collect` keeps working after `shutdown` (the OTLP exporter's own `export` guard was fixed separately — see "Fixed" above). **Open PR**: [#2428](https://github.com/open-telemetry/opentelemetry-ruby/pull/2428).

### Stable — partial / behavioral deviations

- **View `attribute_keys` is not an allow-list** (SDK-13): still merges extra literal key/value pairs onto measurements instead of filtering. No exclude-list either. **Open PR**: [#2426](https://github.com/open-telemetry/opentelemetry-ruby/pull/2426).
- **View `meter_schema_url` selection criterion missing** (SDK-12) — blocked on schema_url support landing generally (see above).
- **View `description`/`exemplar_reservoir` stream-config overrides not supported** (SDK-13, SDK-53). **Open PR**: [#2427](https://github.com/open-telemetry/opentelemetry-ruby/pull/2427) (explicitly leaves `schema_url` out, deferred).
- **Views added after instrument creation don't retroactively apply** (SDK-6) — only `add_metric_reader` is retroactive; `add_view` isn't. **Open PR**: [#2425](https://github.com/open-telemetry/opentelemetry-ruby/pull/2425).
- **Duplicate-instrument-registration warning over-fires** (SDK-36) — warns on any name reuse, even when all identifying fields are actually identical. **Open PR**: [#2417](https://github.com/open-telemetry/opentelemetry-ruby/pull/2417).
- **Advisory parameters are accepted by the API but dropped by the SDK** (SDK-41/42/43, reclassified from N/A now that API-12/13 exist) — `create_instrument`'s `advisory` argument is never stored, validated, or threaded into aggregation/stream configuration. No open PR found; `meter.rb:66` carries an explicit `TODO` acknowledging this. (Two older, likely-stale PRs — [#1801](https://github.com/open-telemetry/opentelemetry-ruby/pull/1801) and [#1703](https://github.com/open-telemetry/opentelemetry-ruby/pull/1703) — predate #2309's API-level advisory-parameter work and would need rebasing to still apply; their `mergeable` status is `UNKNOWN`.)
- **`MetricReader#Collect` returns raw data, not a status** (SDK-55) — no success/failure/timeout signal. **Open PR**: [#2430](https://github.com/open-telemetry/opentelemetry-ruby/pull/2430).
- **`ExemplarReservoir` implementations aren't internally thread-safe** (SDK-65). **Open PR**: [#2397](https://github.com/open-telemetry/opentelemetry-ruby/pull/2397) (draft).
- **`OTEL_EXPORTER_OTLP_METRICS_DEFAULT_HISTOGRAM_AGGREGATION` env var unread** (OTLP-3). **Open PR**: [#2389](https://github.com/open-telemetry/opentelemetry-ruby/pull/2389).
- **No explicit NaN/Infinity policy** (SDK-63) in any aggregation's `update` path. **Open PR**: [#2424](https://github.com/open-telemetry/opentelemetry-ruby/pull/2424).
- **Data point `flags` exists everywhere now but is hardcoded to `0`** (DM-9) — downgraded from "missing entirely" but no mechanism anywhere sets it to signal a stale/no-recorded-value series. No open PR found.

### Development — missing entirely (upstream still in flux; lower urgency)

- **`MeterConfigurator` / `MeterConfig`** (SDK-4, SDK-8, SDK-35) — no way to disable a `Meter` or configure it dynamically.
- **`view_matching_mode` / `composable` View merging** (SDK-7) — only "independent" mode exists (which is, correctly, the spec's own default).
- **SDK self-observability** (SDK-66).
- **`maxExportBatchSize`** on the periodic reader (SDK-57) — every collected batch is sent as a single `Export` call, unconditionally.
- **Exponential histogram NaN/Inf handling** (SDK-21) — same underlying gap as SDK-63, called out separately because this section of the spec is still Development status. **Open PR**: [#2424](https://github.com/open-telemetry/opentelemetry-ruby/pull/2424) (same PR as SDK-63).
- **Per-timeseries async cumulative start timestamps** (SDK-28) — uses a simplified first-write-wins timestamp rather than distinguishing "first series in first collection" from "first occurrence in a later collection."
